REAL LIMITS
- Current CreateFileW subset: fully shared opens (share=7), no custom security/
  template, normal attributes; CREATE_NEW, OPEN_EXISTING, TRUNCATE_EXISTING.
- Other sharing modes, CREATE_ALWAYS/OPEN_ALWAYS, overlapped I/O, named objects,
  full directory/Win32 metadata semantics are explicitly unsupported.
- Native separate file opens still use snapshot-style file contexts, not a
  complete stable mutable-file object model. File-sharing/rename/unlink semantics
  need further work before being declared Windows-equivalent.
- Registry, dynamic DLL loading/unloading/TLS publication, full SEH/unwind,
  API-set DLLs, Windows process/sandbox/UI/network contracts remain unfinished.
- Root-based executable-resource launch is not exposed yet; EXEC is reserved
  authority. Existing unsealed native/ELF/Linux exec regressions pass.
- IOCP requires genuine completions and runnable-consumer concurrency; queues/
  event counters alone are not claimed equivalent. No IOCP implementation yet.
- No physical Dell test; old timers/CPU fallback/ORA/FlowSched/graphics unchanged
  except necessary generic root-policy inheritance, FD/FS/IPC authority/lifetime.
