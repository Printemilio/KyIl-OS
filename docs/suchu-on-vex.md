# Suchu on Vex

Suchu runs natively on Vex: the interpreter, windows (raylib, see
[raylib-on-vex.md](raylib-on-vex.md)), the translation to OCaml, and native
compilation through ocamlopt, as and ld running on Vex itself (see
[native-toolchain.md](native-toolchain.md)).

## Trying it

Open the Terminal (Super, type `terminal`, Enter) and type:

```
suchu run /usr/share/suchu/examples/gui/hello_gui.suchu
suchu run /usr/share/suchu/examples/gui/calculator.suchu
suchu run /usr/share/suchu/examples/games/raycaster.suchu
suchu run /usr/share/suchu/examples/basic.suchu
suchu comp /usr/share/suchu/examples/gui/counter.suchu -o /tmp/counter
run /tmp/counter
write /tmp/hello.suchu print("hello from Vex");
suchu run /tmp/hello.suchu
```

A window opens next to the Terminal; the Terminal waits until it is closed
(its red button). `run <path> [args...]` runs any native program with
arguments (quotes group an argument); `suchu ...` is short for
`run /usr/bin/suchu ...`. Programs get `PATH=/usr/bin:/bin`, `TMPDIR=/tmp`,
`HOME=/home/root`. Use absolute paths: there is no working directory per
shell yet.

`suchu comp` takes ~15 s for a console program and longer for a window
program (it links raylib; the toolchain is slow, see native-toolchain.md);
`suchu run` starts at once.

Examples: `/usr/share/suchu/examples` (`gui/`, `games/`, console ones at
the top); upstream differential programs: `/usr/share/suchu/differential`.

## What is included

* `/usr/bin/suchu` -- run, build, comp, repl (repl needs blocking keyboard
  input, which the console does not provide yet), with the GUI and audio
  backends.
* `/usr/lib/suchu` -- `suchu_core.cmxa` (lexer, parser, runtime, stdlib,
  transpiler), `suchu_eval.cmxa` (interpreter), `suchu.cmxa` (Gui_backend,
  Audio_backend, the embedded Liberation typeface), and raylib with its
  OCaml bindings, which `suchu comp` links for window and audio programs.

Differences from Suchu on Windows/Linux:

* Drawing is done in software. Custom shaders (`scene` lighting shader,
  shader effects) are ignored; shapes, text, images, canvases and 3D scenes
  are drawn.
* `audio` works but is silent: Vex has no sound driver yet.
* `http` is not available (TLS is not ported): `suchu comp` refuses such a
  program, `suchu run` fails when it is imported.
* File/folder dialogs (`choose_file`...) answer "cancelled": there is no
  dialog program on Vex.
* The clipboard is per program.
* `suchu comp --bundle` needs dune and is not available.

## Sources and build

`userspace/suchu` is a copy of the Suchu repository's `src/` (core, eval,
desktop backends except http, cli), `tools/embed_fonts.ml`,
`assets/fonts`, `examples/` and `tests/differential`. Two files differ from
upstream:

* `src/cli.ml` -- does not register the HTTP backend; `suchu comp` calls
  `ocamlopt` with `/usr/lib/suchu` (or `$SUCHU_LIB`) instead of ocamlfind,
  links raylib for window/audio programs, and refuses http programs.
* `src/suchu_cli.ml` -- calls `Cli.main` (plain module) instead of
  `Suchu.Cli.main` (wrapped dune library).

`src/dune.upstream` is the original dune file, for reference. The
`Suchu` module that compiled programs name (`Suchu.Gui_backend`) is
generated by the build as an alias module over Gui_backend and
Audio_backend, as dune's wrapped library would provide.

```
scripts/build-raylib.sh                        # raylib + bindings (once)
scripts/build-suchu.sh                         # needs the OCaml cross toolchain
scripts/run-native-tests.ps1 -Disk Keep        # suite `suchu`
```

The `suchu` native test runs the examples, checks error statuses (2 parse,
3 runtime), `suchu build`, and compiles five programs with `suchu comp`,
requiring their output to equal the interpreter's (the upstream
differential check).
